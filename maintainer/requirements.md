# Requirements and implementation evidence

This matrix tracks the Goldman Sachs **AI Control Layer** task and the submitted FastFence feature description against the current implementation. Sources are the supplied **CRIETRIA AI Control Layer.pdf**, **RULES AI Control Layer.pdf**, and the project submission. It is a traceability record, not a jury score or security certification. Tests listed below are reproducible verification targets; historical measurements retain their original scope in [Testing](testing.md).

## Verification checkpoints and remaining evidence

This reconciliation was made on 2026-10-04. FF-090 records the 1.0.0 release checkpoint of 984 tests and 92.36% source coverage; these numbers are historical, not a fresh result for later changes. FF-086 records an isolated installed candidate wheel whose ordinary `init` installed actual pinned Laya, followed by allowed benign input and pre-upstream attack denial. The configured Qwen4b model already existed locally. FF-084 records eight actual official ACP SDK acceptance groups with separate peer/client and gateway environments. FF-092 verifies public 1.0.0 through `uv tool run` in a clean directory, including configuration-only initialization and cached offline `doctor`.

The subsequent FF-095/FF-098 independent regression run passed 58 focused tests covering restored-output semantic reinspection, pre-OCR authorization and budgets, cancellation, Markdown and OCR boundaries. These changes target 1.0.1. The exact 1.0.1 build and public installation must pass release verification before the corresponding documentation is deployed; this record does not claim that an unpublished release has already passed public-index tests.

The real Laya component report `evaluation/results/training-prompts-laya.json` contains 186 true positives, 187 true negatives, 14 false negatives and 13 false positives across 400 synthetic Qwen-generated and Qwen-labelled cases. This is development evidence, not an independent human-labelled accuracy guarantee. Default input/output semantic latency and throughput under representative concurrent load need broader evaluation; older deterministic-only measurements do not establish a default-runtime SLA.

The OCR report `evaluation/results/ocr-local.json` covers five synthetic fixtures with fresh-worker p50 3165.57 ms and p95 3732.22 ms, excluding HTTP and model inference. It establishes those local examples, not broad document recall or faithful table reconstruction. FFR2 benchmark timings measure crypto alone. None of these scoped measurements imply universal detection, coordinated cross-instance budgets or a speculative readiness score.
